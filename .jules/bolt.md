## 2024-05-18 - Uncontrolled inputs for Performance in Chalamandra
**Learning:** The main input textarea in `App.tsx` was previously using a controlled React state (`useState`) and triggering a full component re-render on every keystroke. Given the complexity of the UI and the underlying extension logic, this caused unnecessary render cycles and degraded perceived input performance, which is a key bottleneck in a UI-heavy extension context.
**Action:** Convert frequent-update textareas to uncontrolled components using `useRef`. Always evaluate if intermediate state during typing is actually needed by the rest of the application or if the value is only needed at submission time (e.g. clicking 'Decodificar' or 'Disrupt'). When making this change, ensure closures and async functions read `ref.current.value` directly or are passed the value as an argument to avoid stale state.
